# 자동 플레이 실험 설계 (초안, 드라이버 작성 전)

## 왜 실험인가
세이브(사후 기록)로는 선택의 효과를 알 수 없다. 오퍼 목록과 시즌별 상점·육성 이력이 없고,
숨은 속성(hiddenCurve, potentialGrade, developmentStyle, hiddenDurability)이 커리어마다 달라 교란된다.
같은 조건에서 선택만 바꿔 보려면 정책을 무작위로 배정해 여러 커리어를 돌려야 한다.

## 설계
- 단위: 커리어 1개. 결과: 발롱도르 수상 횟수, 시즌별 `ballonRank`, 최고 OVR, 은퇴 나이.
- 정책 변수(후보): 포지션, 집중 육성 세트, 이적 방침(최고 오퍼 / 잔류 / 강팀 우선), 상점 구매 여부, 주장 수락 여부.
  변수마다 2~3개 수준으로 제한한다. 변수가 많으면 커리어 수가 폭증한다.
- 배정: 커리어마다 정책 조합을 무작위로(또는 균형 설계로) 배정하고, 배정 값을 로그로 남긴다. 사람이 고르면 교란된다.
- 숨은 속성: 시작 시점에는 보이지 않으므로 무작위 배정이 교란을 상쇄하는 유일한 방법이다. 종료 후 세이브에서 읽어 공변량으로 기록한다.
- 기록: 커리어 종료 시 localStorage 덤프 -> `from_save.py` -> 기존 분석 파이프라인. 정책 로그를 커리어 id와 조인한다.

## 표본 크기에 대한 경고
- 커리어 당 발롱 수상은 0~수 회에 분산이 크다(관측 0~4, 외부 보도 최고 12는 근거 약함). 정책 간 차이를 가르려면 정책당 수십 커리어가 필요할 수 있다.
- 한 커리어가 수십 시즌이라 시간이 오래 걸린다. 허가된 속도·횟수 제한 안에서 몇 커리어가 가능한지는 제한 값을 받은 뒤 계산한다.
- 먼저 파일럿(수 커리어)으로 한 커리어의 소요 시간과 변동성을 재고, 그 값으로 필요한 표본을 다시 추정한다.

## 선행 조건
1. 허가 답변의 제한 값 확인 (`bot/config.example.json` 채우기).
2. `bot/recon.py`로 화면을 기록해서 실제 DOM 확인.
3. 한 커리어를 사람 대신 끝까지 진행하는 드라이버. 처음엔 한 탭, 사람 속도에 가깝게.
