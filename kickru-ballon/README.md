# kickru-ballon

"벤치에서 발롱까지"(https://kickru.com/)의 발롱도르 판정을 **관측 데이터로 추정**하기 위한 1단계 도구입니다.
게임을 대신 플레이하지 않습니다.

## 구성

| 경로 | 역할 |
|---|---|
| `SKILL.md` | Chrome에서 쓰는 수집 스킬 (localStorage 읽기 전용 덤프) |
| `data/seed/*.json` | 직접 옮겨 적은 시드 (Ikarus 13행, 데이터A 16행. 순위 확인 시즌은 이보다 적음) |
| `data/raw/` | 수집한 덤프 (git 제외) |
| `data/real/` | 덤프에서 변환한 시즌 기록 (원본 세이브 기준) |
| `scripts/validate.py` | 스키마·정합성 검사 |
| `scripts/explore.py` | 포지션별 기술통계, 순위 상관 |
| `scripts/from_save.py` | 실제 세이브(덤프) -> 스키마 변환 (`data/real/`) |
| `scripts/compare.py` | 수작업 시드와 원본 세이브 대조 |
| `scripts/ingest.py` | 범용 덤프 구조 확인(`inspect`)과 매핑 변환(`convert`) |
| `tests/` | `python3 -m unittest discover -s tests` |

파이썬 3 표준 라이브러리만 씁니다 (3.13에서 확인).

## 실행

```
python3 scripts/validate.py data/seed/*.json
python3 scripts/explore.py data/seed/*.json
python3 -m unittest discover -s tests
```

`python3 -I`는 스크립트 폴더를 import 경로에서 빼므로 쓰지 마세요. 대신 데이터가 있는 폴더가 아니라 이 폴더에서 실행합니다.

## 스키마와 결측

문서 7장 스키마에 `position`(시즌별, 전환 시즌 구분용), `source`를 더했습니다.
결측은 **0이 아니라 null**이며 분석에서 제외합니다. `ballon_status`는 `won / ranked / not_candidate / unknown`입니다.

- `not_candidate`(NC)는 점수 0이 아니라 "후보 컷 밖"입니다. 순위는 null이며, 순위 상관에서는 가정을 명시한 별도 표로만 다룹니다.
- 시드는 화면을 보고 옮긴 값이라 오독 가능성이 있습니다 (`source: seed:docx-3`). 실제 세이브와 대조되면 `source`가 바뀝니다.

## 시드 데이터에서 확인된 것 / 확인 안 된 것

확인된 것(데이터 자체의 사실):
- 수상 연도 6개가 문서와 일치: Ikarus 2037·2040·2041·2045, 데이터A 2033·2036.
- UCL 우승이 수상의 **충분조건이 아님**: Ikarus 34/35는 리그·UCL 우승인데 8위.

확인 안 된 것(이 데이터로 판별 불가):
- 후보 컷, 상대평가 여부(H9), 월드컵 효과(H6), 포지션별 기준.
- 회귀·가중치. 표본이 캐릭터당 10여 시즌이라 하지 않았습니다.

데이터 안의 의문점:
- Ikarus 42/43은 평점 7.64, G+A 59인데 NC입니다. 같은 캐릭터의 8위(7.48)나 26위(7.32)보다 지표가 좋습니다.
  리그 2위가 원인일 수 있으나(H8, 가설) 표본 1개라 단정할 수 없고, 오기록일 가능성도 있습니다. 실제 세이브와 먼저 대조하세요.
- 문서 7장 예시의 "2036/37 나이 29"와 3장의 "46/47에 38세"는 서로 맞지 않습니다(10시즌 차이라면 39세). 그래서 `age`는 비웠습니다.

## 실제 세이브에서 확인된 것 (2026-10-23 덤프)

localStorage 키 `second-life-football-legends-v2` 하나에 커리어 2개(이카루스, 데이터A)가 들어 있습니다.
값은 JSON 문자열 배열이고 원소를 한 번 더 파싱해야 합니다.

- **시즌별 발롱 순위가 저장돼 있습니다**: `life.history[].ballonRank`. 필드가 없는 시즌은 후보 탈락(NC)입니다.
  시드의 발롱 라벨은 비교한 칸 모두 원본과 일치했습니다.
- **요약 화면의 골·도움·평점 = 클럽 `stats` + 선택된 대표팀 대회 `nationals[].stats`** (친선 제외).
  Ikarus 45/46으로 확인: 클럽 22G17A + 월드컵 2G6A = 24G23A, 평점 7.32. 평균 평점은 `ratingSum / apps`입니다.
- 발롱도르 수상 시즌의 `awards`에만 `value`, `benchmark`가 있습니다(예: 5.83 / 4.6). 수상 6건 모두 value >= benchmark이고
  하나는 value == benchmark(3.97)입니다. **이 값의 의미는 확인되지 않았습니다.** 같은 시즌의 MVP는 value < benchmark인데도
  수상 항목에 들어 있어서, benchmark를 수상 기준선으로 단정할 수 없습니다. 비수상 시즌에는 이 값이 저장되어 있지 않습니다.
- 시드 오독 정정: Ikarus 35/36 UCL은 16강이 아니라 8강이고, 43/44는 2위입니다. 문서에 없던 Ikarus 2031/32~2033/34, 2047/48~2048/49 시즌도 있습니다.
- 세이브에는 현재 포지션만 있고 시즌별 포지션은 없습니다. 이카루스의 ST->CAM 전환 시즌은 문서 기준(46/47)으로 `--switch` 지정했습니다.

실제 데이터로 본 관찰 (탐색적, 표본 작음):
- Ikarus 44/45는 평점 7.44 / G+A 46으로 수상했고, 42/43은 7.64 / 59인데 후보 탈락입니다. 개인 스탯만으로는 설명되지 않습니다.
- 43/44는 UCL 우승, 평점 7.67인데 2위입니다. UCL 우승은 충분조건이 아니라는 점은 유지됩니다.

## 선택지 이력 (세이브에 남는 것 / 안 남는 것)

있음:
- `life.storyLog[]`: 선택 이벤트(`kind: choice`, 제목·`picked`·`others`), 계약(`sign`: 이적/재계약/잔류, 이적료·주급), `decline`(오퍼 거절), `extend`.
  데이터A 25건(선택 9), 이카루스 35건(선택 13). 변환본 시즌 행의 `decisions`에 로그 연도 기준으로 붙인다.
- `core.history[].overall`(OVR), `.rank`(리그 순위), 시즌별 `changes`(능력치 변화), `events`.

없음 또는 불완전:
- **오퍼 목록**: `sign`에는 `passed`(거절한 대안)만 있고 대부분 비어 있다. 이적 시 어떤 구단들이 제안했는지 알 수 없다.
- **시즌별 상점 구매·집중 육성·훈련 목표**: 현재 값(`shop.owned`는 순서 없는 목록, `focus`, `trainingTargets`)과 마지막 `thisSeason`만 있다. 시즌별 이력은 없다.
- 이적 횟수가 커리어당 4~5회, 선택 이벤트도 10여 건이라 **선택 -> 결과 관계를 통계로 추정할 수 없다.**
  게다가 선택의 효과(능력치 변화)와 숨은 속성(`hiddenCurve`, `potentialGrade`, `developmentStyle`, `hiddenDurability`)이 섞인다.
  두 커리어는 속성이 달라서(데이터A: early/rising/dribbler, 이카루스: normal/elite/speed) 비교도 교란된다.

OVR: `core.history[y].overall`은 시즌 y 시작 시점으로 보인다. 시드의 '시즌 종료 OVR'과 y+1 값을 비교하면 16칸 중 13칸이 일치하고
불일치 3칸(31/32 86 vs 87, 34/35 89 vs 90, 45/46 82 vs 91)은 원인 미확인이다. OVR을 모델 입력으로 쓰기 전에 더 확인해야 한다.

## 약관 검토 (사용자 보고, 2026-10-23, 이 세션에서는 /terms 열람 불가라 미검증)

- 자동화·봇·스크립트를 직접 다루는 조항은 없다. 제3조(랭킹 참여)에 "조작 기록의 반복 등록, 과도한 자동 요청 등은 허용하지 않습니다"가 있다.
- 기기 내 자동 플레이의 허용·금지 문구는 없다. 결론은 "불명확"이며 "허용"이 아니다.
- 은퇴 기록은 랭킹에 자동 등록된다(제3조). 대량 자동 플레이는 곧 랭킹 요청으로 이어질 수 있다.

| 경로 | 상태 |
|---|---|
| 받은 덤프 분석, 직접 플레이로 표본 확대 | 진행 |
| 브라우저 자동 플레이 | **보류.** 운영팀의 서면 확인 + 랭킹 자동 등록을 끌 수 있다는 확인 전에는 만들지 않는다 |

문의문 초안: `docs/inquiry-draft.md` (발송은 사용자가 직접).

## Chrome 스킬로 쓰기

`SKILL.md`가 스킬 본체입니다. Claude in Chrome이 이 폴더를 어떻게 불러오는지(업로드 형식 등)는 이 환경에서 확인하지 못했습니다.
스킬 업로드가 필요하면 `SKILL.md`만 담은 폴더를 압축해 쓰세요. 분석 스크립트는 Chrome 쪽에서 실행되지 않을 수 있습니다.
